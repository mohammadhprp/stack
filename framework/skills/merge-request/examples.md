# Examples

- Read the GitLab MR template and current branch history before drafting the request.
- Summarize related commits into concise user-facing bullets while leaving the checklist unchanged.
- Resolve the target branch from the request, host metadata, or repository before comparing changes; do not assume `develop`.
- Display the complete MR plan. Preparation stops there; creation or updates proceed when publishing and any needed push are authorized.
- Update the existing open MR rather than creating a duplicate, preserving unrelated description content and checked items.
